# 2.5 – September Transactions

This is the hardest one. It uses **both tables**. Take it slowly.

## Given
- `tblCustomers` has the **names**.
- `tblInvoices` has the **invoices** and the **dates**.
- The two tables are linked by **CustomerID**.
- Example outputs:
  - Found, with September invoices: 6 lines per invoice, then a blank line.
  - Found, but no September invoices: `No Transactions For September`
  - Not found: a box saying `Account Not Found! Search Again`

## Asked
1. Ask for a customer's **name**.
2. Check that the customer exists. If not, say so and **ask again**.
3. Show all **their** invoices from **September**.
4. If there are none, say `No Transactions For September`.

## Think first
The name is in one table and the invoices are in the other. So we need **two jobs**:

```
  Job 1: tblCustomers          Job 2: tblInvoices
  name  ──────►  CustomerID  ──────►  their invoices
```

- **Job 1** = Pattern C (search and stop): find the name and remember the CustomerID.
- **Job 2** = Pattern B (visit every row): show the ones with our CustomerID **and** month 9.

"Ask again until found" means a **repeat ... until** loop around Job 1.

## In the Delphi IDE
1. Check that **DateUtils** is in the `uses` list (see [00-before-you-start](00-before-you-start.md)).
2. **F12** to the form.
3. Double-click **2.5 – September Transactions**.

## Build the code step by step

**Step 1: The variables.**
```delphi
var
  sName: String;          // the name typed in
  sOnline: String;        // 'Yes' or 'No'
  iCustomerID: Integer;   // remembered from Job 1
  bFound: Boolean;        // did we find the customer?
  bHasSeptember: Boolean; // did we show any invoice?
```

**Step 2: Get ready.**
```delphi
  redQ2.Clear;
  bFound := False;
  iCustomerID := 0;
```

**Step 3: Job 1, the "ask again" loop.** Write the empty shell first:
```delphi
  repeat
    sName := Trim(InputBox('September Transactions', 'Enter the customer''s first name:', ''));

  until bFound or (sName = '');
```
- `repeat ... until` always runs **at least once**. That is perfect, because we must ask at least once.
- `(sName = '')` lets the user escape by pressing Cancel. Otherwise they are stuck forever.
- `Trim` removes extra spaces.
- `''` inside text shows **one** `'` on screen: customer's.

**Step 4: Inside the repeat, search tblCustomers** (Pattern C):
```delphi
    if sName <> '' then
    begin
      tblCustomers.First;
      while (not tblCustomers.Eof) and (not bFound) do
      begin
        if UpperCase(tblCustomers['FirstName']) = UpperCase(sName) then
        begin
          bFound := True;
          iCustomerID := tblCustomers['CustomerID'];
        end
        else
          tblCustomers.Next;
      end;

      if not bFound then
        ShowMessage('Account Not Found! Search Again');
    end;
```
- `UpperCase` on **both** sides means `jenny`, `JENNY` and `Jenny` all match.
- When we find the name, we **save the CustomerID**. That is the key to Job 2!

**Step 5: Job 2, after `until`, show the September invoices** (Pattern B):
```delphi
  if bFound then
  begin
    bHasSeptember := False;
    tblInvoices.First;
    while not tblInvoices.Eof do
    begin
      if (tblInvoices['CustomerID'] = iCustomerID) and
        (MonthOf(tblInvoices['DateofTransaction']) = 9) then
      begin
        bHasSeptember := True;
        // ... show the 6 lines (Step 6) ...
      end;
      tblInvoices.Next;
    end;

    if not bHasSeptember then
      redQ2.Lines.Add('No Transactions For September');
  end;
```
- `MonthOf(date)` gives the month as a number: January = 1 ... **September = 9**.
- **Both** must be true: it is *our* customer **and** it is September.
- `bHasSeptember` is a second flag. It remembers whether we showed anything.

**Step 6: Show the 6 lines** (this replaces the `// ... show the 6 lines ...` comment):
```delphi
        if tblInvoices['OnlineTransaction'] = True then
          sOnline := 'Yes'
        else
          sOnline := 'No';

        redQ2.Lines.Add('Invoice ID:' + tblInvoices.FieldByName('InvoiceID').AsString);
        redQ2.Lines.Add('Customer ID:' + tblInvoices.FieldByName('CustomerID').AsString);
        redQ2.Lines.Add('Number Ordered:' + tblInvoices.FieldByName('NumberOrdered').AsString);
        redQ2.Lines.Add('Number Delivered:' + tblInvoices.FieldByName('NumberDelivered').AsString);
        redQ2.Lines.Add('Online Transaction: ' + sOnline);
        redQ2.Lines.Add('Date of Transaction:' +
          FormatDateTime('yyyy/mm/dd', tblInvoices['DateofTransaction']));
        redQ2.Lines.Add('');
```
- True/False is changed to **Yes/No** so people can read it.
- `FormatDateTime('yyyy/mm/dd', ...)` shows the date as `2024/09/04`, like the example.
- `Lines.Add('')` adds the empty line between invoices.

## Test it
| Type in | What should happen |
|---|---|
| `Jenny` (customer 2) | Invoices 101 and 102 are shown |
| `jenny` | The same, because UpperCase makes it match |
| A name with no September invoices (customer 3) | `No Transactions For September` |
| `Bob` (not in the table) | "Account Not Found! Search Again", then the box asks again |
| Press **Cancel** | It stops asking |

## Common mistakes
- **Forgetting DateUtils.** You get the error `Undeclared identifier: 'MonthOf'`.
- **Searching tblInvoices for the name.** The name is not in that table! Turn the name into a CustomerID first.
- **Putting Job 2 inside the repeat loop.** Keep the jobs apart: find the customer first, then show the invoices.
- **Writing `MonthOf(...) = 'September'`.** MonthOf gives a **number**, so compare with `9`.

## Exam tip
When a question gives you **a name but needs the other table**, think:
> "Use the first table to get the **ID**, then use the ID in the second table."

That link field (here `CustomerID`) is shown by the **1 to ∞ line** in the relationship picture.

> Note: The question says "name", but the examples say "Customer ID 2". We search by first name, because that is what the instructions say.
