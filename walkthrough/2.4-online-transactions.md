# 2.4 – Online Transactions

## Given
- `OnlineTransaction` is True (bought online) or False (bought in the store).
- The example output:
```
Percentage of Online Transactions vs In Store Transactions
Online:75%
In Store:25%
```

## Asked
Work out what **percentage** of transactions were online, and what percentage were in store.

## Think first
To get a percentage you need two numbers:
> **percentage = part ÷ total × 100**

For example: 3 online out of 4 in total gives 3 ÷ 4 × 100 = **75%**.

So the plan is:
1. **Count** the online ones and the in-store ones (Pattern B + Pattern D).
2. Total = online + in store.
3. Work out both percentages.
4. Show them.

## In the Delphi IDE
1. **F12** to the form.
2. Double-click **2.4 – Online Transactions**.

## Build the code step by step

**Step 1: Make the variables.**
- Counters are whole numbers, so they get `i`.
- A percentage can have a comma (like 33.3), so it is a **Real** and gets `r`.
```delphi
var
  iOnline, iInStore, iTotal: Integer;
  rOnlinePercent, rInStorePercent: Real;
```

**Step 2: Clear the box and start the counters at 0.**
```delphi
  redQ2.Clear;
  iOnline := 0;
  iInStore := 0;
```

**Step 3: The counting loop.** True adds to online, False adds to in store.
```delphi
  tblInvoices.First;
  while not tblInvoices.Eof do
  begin
    if tblInvoices['OnlineTransaction'] = True then
      Inc(iOnline)
    else
      Inc(iInStore);
    tblInvoices.Next;
  end;
```
`Inc(iOnline)` means the same as `iOnline := iOnline + 1`.

**Step 4: The maths, after the loop.**
```delphi
  iTotal := iOnline + iInStore;
  rOnlinePercent := iOnline / iTotal * 100;
  rInStorePercent := iInStore / iTotal * 100;
```
`/` always gives a Real, which is why the answers go into `r` variables.

**Step 5: Show it like the example.**
```delphi
  redQ2.Lines.Add('Percentage of Online Transactions vs In Store Transactions');
  redQ2.Lines.Add('Online:' + FloatToStrF(rOnlinePercent, ffFixed, 5, 0) + '%');
  redQ2.Lines.Add('In Store:' + FloatToStrF(rInStorePercent, ffFixed, 5, 0) + '%');
```
`FloatToStrF(number, ffFixed, 5, 0)` turns a Real into text:
- `ffFixed` means a normal number.
- `5` is the most digits allowed.
- `0` means **0 decimal places**, so `75` and not `75.00`.

## The whole answer
The answer file also has an `if iTotal > 0` check around Steps 4 and 5. It stops a crash if the table is empty, because you can never divide by 0. The question did not ask for it, so it earns no marks, but it is a good habit.

```delphi
procedure TfrmQ2.btnQ2_4Click(Sender: TObject);
var
  iOnline, iInStore, iTotal: Integer;
  rOnlinePercent, rInStorePercent: Real;
begin
  redQ2.Clear;
  iOnline := 0;
  iInStore := 0;
  tblInvoices.First;
  while not tblInvoices.Eof do
  begin
    if tblInvoices['OnlineTransaction'] = True then
      Inc(iOnline)
    else
      Inc(iInStore);
    tblInvoices.Next;
  end;
  iTotal := iOnline + iInStore;
  if iTotal > 0 then
  begin
    rOnlinePercent := iOnline / iTotal * 100;
    rInStorePercent := iInStore / iTotal * 100;
    redQ2.Lines.Add('Percentage of Online Transactions vs In Store Transactions');
    redQ2.Lines.Add('Online:' + FloatToStrF(rOnlinePercent, ffFixed, 5, 0) + '%');
    redQ2.Lines.Add('In Store:' + FloatToStrF(rInStorePercent, ffFixed, 5, 0) + '%');
  end;
end;
```

## Test it
- The two percentages must **add up to 100**.
- Count the ticks in the grid yourself, and do the maths on paper. Does it match?
- Your numbers may not be 75% and 25%. That is fine! The example is just to show the **layout**. Your code must work out the real answer from the data.

## Common mistakes
- **Forgetting to set the counters to 0.** They start with junk numbers.
- **Doing the maths inside the loop.** Do it once, **after** the loop, when counting is finished.
- **Using `div`.** `div` throws away the part after the comma, so 3 div 4 = 0. Use `/`.
- **Typing `'75%'` straight into the code.** That is hard-coding, and gets no marks.

## Exam tip
Every percentage question is: **count in the loop, then do the maths after the loop.**
